# DNAAnalyzer free-launch deployment

This is the deployment path for the current no-payment release. The analysis
workspace, dashboard, settings, and billing URLs require a Supabase session.
Checkout is disabled, and every authenticated user receives Researcher features
with a server-enforced limit of 50 new variants per UTC day.

## 1. Deploy the Modal backend

Install and authenticate the Modal CLI on your own machine, then deploy from the
backend directory:

```powershell
Set-Location "C:\Users\Aawaiz\Desktop\variant-analysis-evo2\evo2-backend"
python -m pip install modal
modal setup
modal deploy main.py
```

Before `modal deploy`, create a Modal secret named `api-auth-key` in the Modal
web dashboard and add an `API_KEY` value generated by a password manager. Using
the dashboard keeps the secret out of PowerShell history.

Record the two HTTPS endpoint URLs printed by Modal: the Evo2 prediction
endpoint and the disease-association endpoint. Use the same generated value as
`MODAL_API_KEY` in Vercel. Never add the value to Git.

## 2. Create the production Supabase project

Create a separate Supabase project for production. In SQL Editor, apply these
files in this exact order:

1. `supabase/development-bootstrap.sql` (only if this is a completely empty project)
2. `supabase/profile-settings.sql`
3. `supabase/germline-association-schema.sql`
4. `supabase/snv-disease-pipeline-schema.sql`
5. `supabase/free-access.sql`
6. `supabase/analysis-cache-6-months.sql`

Do **not** run `supabase/paddle-billing.sql` for the free launch. If it was
previously run, apply `free-access.sql` afterward; it removes the paid-history
restriction and installs the free quota functions.

Follow `supabase/imports/README.md` to load required reference data. In
Supabase Authentication settings:

- Enable Email authentication.
- Set the production Site URL to the exact HTTPS Vercel/custom-domain origin.
- Add `https://YOUR_DOMAIN/login` to allowed redirect URLs.
- Configure the Confirm signup email template to display `{{ .Token }}` because
  this application verifies a six-digit email OTP.
- Keep leaked-password protection and email confirmation enabled.

Copy the project URL, public anon key, and server service-role key. The
service-role key must only exist in Vercel's server environment.

## 3. Deploy the Next.js application to Vercel

Import the Git repository into Vercel and use:

| Setting | Value |
| --- | --- |
| Root Directory | `evo2-frontend` |
| Framework Preset | Next.js |
| Node.js | 20.x |
| Install Command | `npm ci` |
| Build Command | `npm run build` |
| Output Directory | leave empty |

Add these variables to the **Production** environment:

```dotenv
ENABLE_PAYMENTS=false
NEXT_PUBLIC_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=YOUR_PUBLIC_ANON_KEY
SUPABASE_SERVICE_ROLE_KEY=YOUR_SERVER_SERVICE_ROLE_KEY
MODAL_ENDPOINT_URL=https://YOUR_EVO2_ENDPOINT.modal.run
DISEASE_MODEL_ENDPOINT_URL=https://YOUR_DISEASE_ENDPOINT.modal.run
MODAL_API_KEY=THE_SAME_SECRET_STORED_IN_MODAL
```

No Paddle variable is required. Do not copy `.env.local` into Git or upload the
file itself; enter values individually in Vercel. Redeploy after changing any
environment variable.

## 4. Connect the domain

Add the custom domain in Vercel, apply the DNS records Vercel provides, and wait
for HTTPS to become active. Then replace the Supabase Site URL and redirect URL
with the final HTTPS domain. Keep the Vercel preview domain in the redirect list
only if you intentionally use preview deployments with the production database.

## 5. Production verification

Run locally before deployment:

```powershell
npm ci
npm run typecheck
npm test
npm run build
```

After deployment, use a new email address and verify all of the following:

1. Visiting `/` while signed out redirects to `/login`.
2. Signup sends a six-digit code and verification opens `/`.
3. Login opens `/`, the analysis workspace.
4. `/dashboard`, `/settings`, and `/billing/checkout` reject signed-out users.
5. The billing page says payments are disabled and has no purchase button.
6. A real test analysis completes through Modal.
7. History belongs only to the signed-in user and CSV export works.
8. `/api/analyze` and the other analysis APIs return 401 without a session.
9. `/api/billing/checkout`, `/portal`, `/status`, and `/webhook` return 503.
10. The 51st distinct variant in one UTC day is rejected; repeated access to a
    completed cached variant is not double-counted.

Check Vercel function logs, Modal logs, and Supabase logs after the test. Never
log auth tokens, service-role credentials, API keys, or submitted genetic data.

## 6. Before inviting real users

- Replace draft legal text with reviewed policies and a real retention/deletion
  process.
- Confirm the production domain in `src/lib/public-site.ts`.
- Configure Supabase backups and test a restore.
- Set a Modal spending limit/alert and watch GPU cold-start/timeout behavior.
- Configure a transactional SMTP provider in Supabase; default test email
  delivery is not suitable for a public launch.
- Add uptime/error monitoring for the Vercel APIs and both Modal endpoints.
